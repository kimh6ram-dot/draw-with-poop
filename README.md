# 똥으로 그리세요

꼬직 인스타그램 팔로워 1만 명 기념 이벤트용 미니게임. 사람 캐릭터를 직접 움직여 원하는 자리에 앉히고, 똥을 한 개씩 싸서 그림을 그린다.

디자인 원칙(3차, 2026-10-07): **UI는 기능만(흰 화면 위 작은 글자), 디테일은 전부 캐릭터의 배변 행동에.**

## 실행
- `index.html`을 더블클릭(file://)하면 바로 열린다. 빌드·서버·의존성 없음(외부는 Pretendard CDN 한 줄).
- 폰 테스트: `node tools/serve.js` → 같은 와이파이의 폰에서 `http://<PC-IP>:8080` (방화벽에 Node 인바운드가 막혀 있으면 열어야 함).
- QA: `node tools/qa.js` (playwright-core + 로컬 Chrome, 스크린샷 `screenshot/qa-*.png`, 배변 10프레임 `qa-motion-*.png`).
- 배포(GitHub Pages 등) 전: `node tools/bump-version.js` (리소스 주소 `?v=` 갱신, BUILD_TEMPLATE R16).
- **배포 주소**: https://kimh6ram-dot.github.io/draw-with-poop/ (저장소 `kimh6ram-dot/draw-with-poop`, Pages = main 브랜치 루트, 2026-10-13 첫 배포). 갱신 절차: bump-version → 커밋 → `git push origin main` → 약 1분 뒤 반영. `screenshot/` 은 .gitignore.

## UI (3차에서 단순화한 것)
- 플레이 화면: 제목 없음. 상단 가운데 `💩 N`(14px, 2026-10-13 좌상단→가운데), 우상단 `되돌리기 처음부터 완성`(글자만, 테두리·배경 없음, 터치 높이 40px, 줄바꿈 없음). HUD는 3열 그리드(여백·카운트·버튼)라 360px 이하 좁은 화면에선 버튼이 먼저 자리를 잡고 카운트가 남는 공간 가운데로 밀린다(겹침 없음).
- 터치 조작: 화살표 4개는 회색 글자만(누르면 검정), 터치 영역 60×60. `💩 싸기`는 터치 영역 160×88 투명, 보이는 건 1px 테두리 작은 알약(높이 40).
- PC: 💩 버튼 없음. 우하단 `SPACE 싸기` 라벨은 2026-10-13 제거하고 안내 문구("SPACE 싸기로 하나씩 그려보세요")에 통합. 모든 카드·패널·박스·검정 큰 버튼·그림자 제거.
- 인트로 `시작하기`는 검정 채움 200×48 버튼(10차), 결과 `작품 저장하기`는 내용 폭의 1px 테두리 버튼, `다시 그리기`는 글자만. 확인창은 흰 상자 + 글자 버튼 2개.

## 배변 애니메이션 (6단계 + 똥 3단계)
`requestPoop()`은 `action === 'idle'`일 때만 수락. 잠금 구간 동안 이동·방향·탭·추가 요청 전부 무시(큐 없음).

| 단계 | 시간 | 캐릭터 | 똥 | 이벤트 |
|---|---|---|---|---|
| stop | 50ms | 걸음 멈춤, 발 모음 | — | `stop` |
| squat | 200ms | 무릎 굽히며 상체 살짝 숙여 완전히 쪼그려 앉음(ease-in-out) | — | `squat` |
| strain | 250ms | 완전히 앉은 채 정지 + 꿈틀 2회(엉덩이 ↓0.03H·상체 →0.03H) + 미세 떨림·눈 질끈 | — | `strain` |
| poop | 250ms | 앉은 채, 힘이 서서히 풀림 | **생성** → emerge 100ms(엉덩이 아래에서 0.25→0.9 크기) → fall 150ms(중력 ease-in, 살짝 늘어남) | `poop` |
| rise | 200ms | 무릎 펴며 빠르게 일어남(ease-out) | land 80ms(scaleX +16% / scaleY −16% → 복원, 바닥 고정) → rest | `land`, `rise` |
| idle | — | 바로 이동 가능 | 최종 위치 고정 | — |

입력 잠금 합계 **0.95초**(착지 squash는 rise 와 겹침). 똥은 완전히 앉은 뒤 0.25초가 지나야 나오기 시작한다.

## 똥 spawn → fall → ground
- 논리 좌표는 생성 즉시 최종값: `{ x, y }` = 바닥 위치(바라보는 방향 반대 14·아래 5), `{ sx, sy }` = 나오는 지점(반대 11·위 8), `t` = 생성 시각.
- 낙하 거리 13유닛(화면 약 14px). 연출은 `renderer.poopAnim(p, now)`가 `t`로부터 계산(emerge/fall/land/rest)하고, 연출 중인 똥은 캐릭터 앞에 그린다.
- 되돌리기·범위 계산·결과 프레이밍·저장 이미지는 `x, y`만 쓴다(연출과 무관).

## 9차 (2026-10-12) — 고정 화면(카메라 추적 제거) · 이동 영역 = 화면 · 인트로 이벤트 블록 재디자인
- **카메라 완전 고정**: 플레이 중 `camera.follow` 호출 제거. 카메라는 월드 중앙(2000,2000)·플레이 배율(모바일 1.1 / PC 1.375)에 고정되고, 캐릭터가 어디로 가도 화면이 스크롤·줌·흔들림 없이 그대로다. 결과 프레이밍(`fitBounds`)·저장 이미지는 이전과 동일하게 독립 계산.
- **이동 영역 = 화면 안**: `main.updateArea()`가 화면 크기·HUD 아래 가장자리·하단 컨트롤(D-pad/싸기/PC 키 안내) 위 가장자리를 실제 DOM 크기로 재서 월드 유닛 영역으로 바꾸고 `world.setArea`로 전달. 좌우 `AREA_SIDE_INSET` 30, 위는 HUD 아래 + 캐릭터 키(머리가 HUD 아래), 아래는 컨트롤 위(발이 컨트롤 위). `world.moveBy`가 이 영역으로 clamp → 가장자리에서 **밈·반동 없이 멈추고**, 막힌 축만 멈추고 다른 축은 계속 움직이며, 가장자리에서도 배변 가능(똥은 화면 안).
- **리사이즈**: `handleResize`·시작·다시 그리기·플레이 전환 시 영역 재계산. 똥 데이터·좌표는 그대로(재배치 없음), 캐릭터만 새 영역 안으로 clamp. 걷기·배변 애니메이션 변화 없음(제자리걸음 아님 — 막힌 축의 이동량이 0이면 걷기 위상이 그만큼 안 진행).
- **인트로 이벤트 블록**(index.html·main.css): 절대 위치 한 줄 캡션 → CTA 아래 흐름 배치. `10,000 FOLLOWERS EVENT`(11px 회색 자간) / 2열 `사수 PICK · 1명 / 5만원` | `추첨 · 10명 / 5천원`(가운데 1px 연회색 세로선 40px) / `참여 안내 @ccojik.dh`(핸들만 bold). 이모지·카드·테두리·그림자 없음, 320px 폭에서도 2열 유지. 최대 폭 300px 가운데 정렬. (10차에서 3줄 텍스트로 대체)
- `world.setPosition(x,y)`(영역 clamp)는 QA 전용 — 화면이 고정이라 오른쪽으로 계속 걷는 검사들 앞에서 캐릭터를 영역 중앙으로 되돌린다(`qa.js recenter`).
- 데드존 상수(`CAMERA_DEADZONE_*`)는 미사용으로 남겨 둠(`camera.follow` 참고용).

## 8차 (2026-10-12) — PC 전체 화면 · 정면/후면 걷기(부위 분리) · 바지 아이보리
- **PC 전체 화면**: `@media (pointer: fine) and (min-width: 600px)` 에서 `.app`의 `max-width:430px` 해제 → 브라우저 전체가 도화지(가시 영역 확장, 늘리기 아님). 캔버스는 CSS 폭×DPR, 리사이즈·visualViewport 처리 그대로. 모바일(터치)은 변화 없음.
- **PC 배율**: `CAMERA_SCALE_PC` 1.375(모바일 1.1의 1.25배) — 마우스·폭 600px 이상이면 적용(`camera.setPlayScale`, 플레이 중 창 크기 변경도 즉시). 캐릭터·똥이 같이 커지고 그림 좌표·비율은 그대로. 결과 프레이밍 상한도 플레이 배율 기준.
- **정면/후면 걷기**: 시트에 정면·후면 걷기 프레임이 없어 `idle_front`/`idle_back`를 **부위 조각**(다리 2·팔 2·몸통)으로 나눠 애니메이션(`build-character.js` `splitParts`, 영역은 프레임 비율 — 밑단 0.84, 다리 x 0.27/0.50/0.73, 팔 y 0.60~0.81·바깥 26%).
  다리는 번갈아 위로만 들어 올려 바지 뒤로 숨고(몸통 조각이 밑단 +2px 를 덮어 이음새 없음), 팔은 소매 끝(+2px 겹침)을 축으로 다리와 반대 위상으로 ±0.14rad, 몸통은 걸음마다 0.015 들썩. 원본 픽셀 변형·늘리기·좌우 흔들기 없음. 값은 `config.CHARACTER_SPRITE.frontLift/frontBob/frontArmSwing`.
  걷기 위상은 이동 거리 기반이라 좌우·상하 모두 걸음 수가 속도와 일치하고, 멈추면 `walkBlend`(140ms)로 다리가 기본 자세로 돌아온다. 확인 시트: `screenshot/char-parts-sheet.png`.

## 캐릭터 방향 · 걷기 · 방향 전환 (5차, 2026-10-08 → 6차에서 8방향 face 로 확장)
- `face` = 마지막 이동 방향의 단위벡터(8방향) — 3D 캐릭터는 이 각도로 실제 회전(대각선은 45°). `dir` = 가장 가까운 4방향(같으면 가로) — 2D 폴백·스프라이트용. 2D 폴백은 옆모습 반전 + 정면/후면 별도 관절 배치.
- 이동 벡터는 정규화(대각선 합성 속도 = 한 축 단독). 두 키가 순서대로 들어오면 먼저 눌린 축 → 대각선으로 yaw 가 70ms 에 걸쳐 부드럽게 따라간다.
- 대각선에서 한 키를 먼저 떼면 남은 한 축을 `FACE_RELEASE_GRACE_MS`(80ms) 이상 유지해야 그쪽을 본다 — 사람 손은 두 키를 동시에 못 떼므로, 없으면 멈출 때마다 45° 움찔한다. 정지 상태의 새 입력(탭)과 키 추가는 즉시 반영.
- 걷기(시각): 걸음 위상이 **실제 이동 거리**로 진행(`WALK_STRIDE` 20유닛 = 한 걸음, 상한 `WALK_MAX_STEP_HZ` 7걸음/s, 남는 거리는 반 걸음까지 이월). 다리 교차·발 들림·팔 반대 위상·몸통 들썩임(머리 60%). 정면/후면은 무릎을 바깥·위로 들고 발을 안으로(행진 "<").
- 시작/정지(시각): `walkBlend`가 90ms에 0→1, 정지 시 140ms에 1→0 — 현재 다리 위치에서 기본 자세로 보간. 탭 한 걸음도 작은 걸음을 내딛는다. **좌표는 입력에 즉시 반응**(보간은 그림만).
- 방향 전환(시각): `turn`(120ms) 동안 이전 방향으로 가로 폭이 좁아졌다 새 방향으로 펴진다(몸을 돌리는 느낌). 배변 중엔 방향도 잠금.
- 똥 위치는 face 로 계산(`world.offsetsFor(face)`, 상수 `POOP_GROUND`/`POOP_SPAWN`): ground = (−fx·14, −fy·6 + (1−|fy|)·5), spawn = (−fx·11, −8 − max(0,fy)·4), front = fy ≤ 0.3. 옆 = 엉덩이 뒤(∓14, +5), **정면 = 몸 뒤(0, −6, 캐릭터 뒤에 그려 다리 사이로 보임)**, **후면 = 발 앞(0, +6, 캐릭터 앞)**, 대각선은 그 사이. 낙하 중 가림은 `p.f`, 놓인 뒤엔 발 기준선 y 비교. 그림 좌표는 생성 즉시 고정.

## 캐릭터 animation state 구조 (에셋 교체 대비)
- `world.snapshot().pose = { state, t, dir, facing, crouch, strain, push, walkPhase, walkBlend, moving, turn, time }`
  - `state`: `walk` · `idle` · `stop` · `squat` · `strain` · `poop` · `rise` × `dir` 4종 조합으로 프레임을 고른다. `t` = 단계 내 진행도 0..1, `walkPhase` = 걸음 위상(rad), `turn` = { from, t } 방향 전환 보간.
  - 임시 선화는 연속값(`crouch`/`strain`/`push`/`walkPhase`/`walkBlend`)으로 관절을 보간해 그린다 — 단계 사이에 자세가 튀지 않는다.
- 교체: `character.js`의 `draw(ctx, pose)`만 바꾼다. 원점 = 발 중심, 단위 = 월드 유닛(키 54). 게임 로직 무수정.
  실제 캐릭터 이미지를 줄 때 필요한 포즈: **4방향 × { idle 1, walk 4~6프레임, squat(앉는 중) 2~3, seated/strain 1~2, rise 2 }** (좌우는 한 벌 반전 가능 → 실제 3방향). 똥은 이미 PNG.
- 포즈 시트 확인: `node tools/qa.js --pose` → `screenshot/qa-pose-sheet.png`(4방향 × idle·걷기 4위상·앉음·힘줌).
  file://에서 캔버스 오염을 피하려면 햄버거 쌓기의 `tools/build-sprites.js`+`png.js`로 base64 내장 패턴을 가져온다.
- 똥 PNG(적용 완료, 2026-10-07): `assets/poop_1~3.png`(사용자 에셋) → `node tools/build-sprites.js` → `src/game/sprites-data.js`(알파 bbox 크롭·2배 축소·base64 내장, 약 347KB) → `sprites.js`가 Image로 로드 → `renderer.poopSprite(배율, 종류)`가 배율별로 래스터(절반씩 단계 축소로 번짐 방지). 플레이·결과·저장 이미지·인트로·배변 연출(나옴/낙하/착지 squash) 전부 같은 경로. 로드 전·실패 시에만 벡터 폴백.
  - **1번이 기준**: `config.POOP_VARIANTS` = poop_1 가중치 70(크기 기준 1.0 = 가로 폭 `POOP_SIZE`), poop_2 15(1.05), poop_3 15. 똥마다 생성 시점에 한 번 고르고(`p.v`) 이후 바뀌지 않는다. 1번만 쓰려면 나머지 weight 0. PNG를 바꾸면 빌드 스크립트만 다시 실행.
  - 글자 속 똥(HUD 카운트·싸기 버튼 라벨·결과 "총 N번"·첫 안내)도 💩 이모지 대신 1번 PNG(`<img class="poop-icon">`, main.js가 src 주입). 저장 이미지의 "총 N번" 왼쪽 아이콘도 같은 스프라이트. 인트로는 2026-10-13부터 캔버스 대신 사진 `assets/main.png`.

- 효과음: `sfx.js`의 `SOURCES`에 `squat/strain/poop/land` 경로를 넣으면 world 이벤트로 자동 재생(첫 제스처 후 unlock).
